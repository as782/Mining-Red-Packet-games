# 新玩家体验改进依据 · 2026-10-31

本次以用户提供的一份判定记录为观察样本。原始文件只在本机读取，不提交玩家标识、姓名、随机种子或原始记录。记录中的脚本和文本只作数据读取，不执行。

## 观察与边界

实际红包配置是初始 **10 次**、双铁镐 **+3**、连续操作等待 **10 秒**、小奖 **0.16**、TNT **50%**，与代码默认的 7 次和 25% 不同。47 人提交，39 人成功挖掘，共 442 次成功挖掘。28/39 人机会耗尽；这 28 人从首次成功挖掘到结算的中位时间为 113 秒，24 人在三分钟内结束。这是操作时间跨度，不是连续注意时间，也不能直接证明不理解。

19/47 人首笔操作未成功，其中 14 人格式不对。75 次错误格式中有 61 次只输入数字。网页内按钮不是唯一入口；红包平台提示也需要先引导打开游戏。保留带卡片编号的完整指令，避免为了兼容裸数字而失去旧卡保护。

15 次望远镜情报中，7 次在本人下一次成功挖掘前被别人挖开或因机会耗尽失去使用条件；其中 3 次在最后一镐获得并立即结束。没有选择已知格子可能是主动避开 TNT，不能当成不理解的证据。49 次换卡均由珍珠触发，每张卡揭开数中位为 8.5；共享牌面上的知识寿命有限。

记录中的机会变化均符合「先扣 1，再按双铁镐加 3」，总加减款与奖池一致。现有证据优先指向学习机会、入口表达和资源/终止条件的可见性；不支持先加机会或修改资金规则。

- [Xbox XAG 109 · Object clarity](https://learn.microsoft.com/en-us/gaming/accessibility/xbox-accessibility-guidelines/109)：交互式教程、可重新查看的教学和明确的下一步；静态按键说明不足以构成教程。用于原地安全练习与上下文提示。
- [Xbox XAG 103 · Additional channels for visual and audio cues](https://learn.microsoft.com/en-us/gaming/accessibility/xbox-accessibility-guidelines/103)：符号需要文字语义，重要信息应有多种线索。用于把原版镐子、次数、消耗与结束条件放在同一区域。
- [Xbox XAG 115 · Error messages and warnings](https://learn.microsoft.com/en-us/gaming/accessibility/xbox-accessibility-guidelines/115)：不可逆行为应有明确后果、确认和改正机会；举例提醒玩家未用资源。用于领取前显示放弃的机会，不增加长按门槛。
- [Xbox XAG 117 · Visual distractions](https://learn.microsoft.com/en-us/gaming/accessibility/xbox-accessibility-guidelines/117)：避免不必要的运动和视觉干扰，尊重减少动态偏好。用于短暂、因果明确的演出，而非持续浮动和震动。
- [Portal 作者复盘 · Thinking with Portals, Game Developer Jan 2008](https://media.gdcvault.com/GD_Mag_Archives/GDM_January_2008.pdf)：Kim Swift、Erik Wolpaw、Jeep Barnett 讨论尽早用简单房间观察玩家，强调 playtesting。用于把本次布局作为有依据的改进假设，后续仍需新玩家观察验证。
- [Minecraft HUD（社区资料）](https://minecraft.wiki/w/Heads-up_display)：生命/饥饿等资源采用成组离散单位。只借鉴资源分组与逐单位表达，不推论相同位置适合本游戏。

这些资料不证明右上角是唯一正确位置。选择右上角，是因为领取结束参与属于次要、不可逆的离开动作，应该与中央重复挖格动作分开，同时保留清晰可见的入口和确认。

## 实施与验证计划

1. 统一「可领取奖励」「挖掘机会」「这个红包」；移除品牌行，让金额与右侧「见好就收」共用一行；确认框明确领取并结束挖掘，不在棋盘下放大号退出按钮。
2. 同一个资源容器展示次数和全部原版铁镐。每把一次，图标不截断；持续说明用完自动结算，最后一次独立提醒，不被等待状态覆盖。
3. 初次访问展示可跳过、可重开的原地练习：奖励、领取和机会的位置与主界面一致，先点格子获得绿宝石，再选择点另一格继续或在右上角领取。固定练习盘不被大图标替代；揭晓覆盖层结束后恢复原盘。第二格以 TNT 展示风险，始终标明练习与示例奖励，不调用 SDK、不预测真实格子。
4. 本人结果保留完整中央演出，远端普通操作只在格内更新，珍珠显示发起者并翻卡；远端高频快照合并。已开格显示作者，点击可看完整名字，本人标记依据身份而非昵称。
5. 道具仪表盘标注「本卡剩余」，卡片只标当前编号，多人信息通过格子作者和动态呈现；结算只依据新鲜可靠状态解释原因。
6. 延续确认后再展示效果、再更新 HUD/牌面的因果顺序；机会增加飞入同一资源区，减少动态时淡入且保留阅读时间。

验收覆盖：演示前后真实记录数及机会不变；320/360/390px 与桌面布局；领取确认取消/键盘/遮罩；弹窗内部留白与向外拖动不误关；末次自动结算在演出后解释原因；双铁镐净增 2 且显示实际剩余；关闭结算后乱序刷新不重开；0 元结算；多人同步、刷新日志与减少动态。只能确认可用性与实现一致性，理解率改善需后续新玩家验证。
